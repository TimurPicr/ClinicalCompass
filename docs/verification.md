- Настоящая `qwen3:4b-q4_K_M`, шесть изолированных случаев `scripts.evaluate_ai`: **6 PASS из 6** по актуальной автоматической рубрике. Проверены улучшение, ухудшение с пропусками/тошнотой, исторический критический сигнал, конфликт аллергий, Андрей без фармакотерапии и prompt injection. Исходный запуск генерации вернул exit code 1 из-за слишком узкой лексической проверки: она не распознала фактически правильное «пациент отрицает аллергию, но врач подтвердил». Эта проверка исправлена, добавлены пять регрессионных примеров; повторная оценка тех же сохранённых ответов завершилась успешно. Слова и выводы модели не менялись.
- В процессе предыдущих прогонов обнаружены ложные AI-предупреждения только по известному диагнозу/аллергии, подмена смысла q9 тревожностью, неправильное связывание нуля q9 с положительным скринингом и обратный порядок дат. Обновлены инструкции и регрессионная рубрика. Схема генерации теперь ограничивает ссылки списком ID пациента; для красного сигнала требуется начало пациентского текста сообщением о срочной оценке. На настоящей Ollama выявлена несовместимость исходного regex с поддерживаемым подмножеством JSON-грамматики; использован проверенный вариант с обычными пробелами и `.*`. Проверки явных дат, сумм и смысла нулевого q9 пересчитаны по сохранённым входам/настоящим ответам без повторной генерации. Локальные артефакты: `var/evaluations/ai-evaluation.json`, `ai-evaluation-initial.json`, `ai-evaluation-attempt2.json`, `ai-evaluation-attempt3.json`, `ai-critical-schema.json`; код и пределы рубрики: [ai-evaluation.md](ai-evaluation.md).

В основной демонстрационной БД приняты настоящие AI-сводки Анны, Павла и Андрея. Задача Марии после трёх попыток осталась `failed` с безопасной диагностикой `ValueError`: её результат не прошёл проверку и не был опубликован; красный сигнал сохранён. Успех шести изолированных регрессий не отменяет этого ограничения. Все четыре исходных статуса после обработки остались green/yellow/red/yellow.

Новые оригиналы документов сохранены и поставлены на OCR; успешная обработка этих четырёх документов пока не заявляется. Визуальный сценарий в браузере в этом проходе не выполнялся. Медицинская экспертная приёмка и проверка на реальных пациентах не проводились. Результат 159 pytest и автоматических эвристик подтверждает перечисленные программные контракты, а не клиническую достоверность AI.

# Предыдущая проверка 23 октября 2026 года

Проверка выполнена на этом Mac с Python 3.13, Node 26, PostgreSQL 16 + pgvector в отдельном Docker Compose проекте `clinicalcompass2`, Ollama 0.40.8, Tesseract rus+eng и Poppler. Данные исключительно синтетические.

Проверенные результаты: **46 backend-тестов pytest и 5 frontend-тестов времени**, сборка React без ошибок, схема Alembic без расхождений.

## Воспроизводимые проверки

```bash
source .venv/bin/activate
python -m pytest -q
npm --prefix app/frontend test
npm --prefix app/frontend run build
python -m alembic check
python -m scripts.smoke_api --base-url http://127.0.0.1:8010
python -m scripts.check_local_ai
python -m scripts.check_local_ai --patient-id 2
```

- Единый `./scripts/dev.sh` проверен: PostgreSQL healthy, миграции, API `/api/health` 200, Vite 5174 HTTP 200, worker и scheduler запущены. При остановке временные процессы убраны, данные сохранены.
- API smoke прошёл несколько раз на настоящем PostgreSQL и HTTP/WebSocket. Проверены одноразовое приглашение, cookie/CSRF, разделение карт и аудит, четыре типа вопросов, неизменяемые снимки, PHQ-9, немедленные правила, версии назначений и приём, дневник, обратная связь врача, реальные файлы и изоляция чата. Это не mock API. Синтетическая история сохранена.
- Миграция применена к новой БД; `alembic check` не обнаружил расхождений схемы.
- Настоящие локальные модели `qwen3:4b-q4_K_M` и `qwen3-embedding:0.6b`: проверены строгий Pydantic JSON, embedding 1024, индексирование и PostgreSQL cosine-distance. Последние реальные AI-анализы всех трёх демонстрационных пациентов №2/3/4 выполнены после фильтрации источников. Дополнительный RAG-прогон по оригинальному руководству авторов PHQ/GAD вернул проверяемые ссылки на страницы 6 и 8; источник и оригинал сохранены локально (подробности в `sources.md`). Синтетический источник не был выдан за медицинское доказательство: модель вернула пустой список клинических ссылок в том прогоне.
- Все три демо-документа обработаны. Документ №1 прошёл настоящий OCR и локальный LLM: одна страница, четыре предложения с проверенными цитатами/страницами; статус оставлен `unconfirmed`. Отдельно проверен сканированный PDF через pdftoppm → Tesseract.
- PubMed E-utilities реально вернул 8 библиографических записей. Недоступный полный текст PMC отмечен `partial`. Обращения к ГРЛС и рубрикатору Минздрава завершились `ConnectTimeout`; ограничения отражены в журнале, ничего не имитировалось.
- Через настоящий временный Cloudflare Tunnel проверены HTTPS `/api/health`, раздача React, вход с Secure-cookie, авторизованный `/api/auth/me` и настоящий WSS WebSocket с проверенной cookie-сессией/CSRF. Временные URL после завершения проверки останавливаются; запуск нового адреса: `python -m scripts.share`.
- Для клинического контекста механически исключены синтетические источники и библиография без полного текста; обычный поиск врача сохраняет их для отладки. После исправления реальные сводки демонстрационных пациентов пересчитаны, прежние результаты оставлены в истории.
- Web Push: pytest проверяет регистрацию/ограничение endpoint, нейтральный текст, дедупликацию и повторные напоминания просроченного регулярного опросника с mock-транспортом. Формат настоящих сгенерированных VAPID-ключей принят py-vapid. Ключи текущего локального запуска хранятся только в игнорируемом `.env`.

## Пределы проверки

- Визуальная проверка браузером не выполнена: доступные средства CUA вернули `browsers=[]`, `Browser is not available: iab` и `cgWindowNotFound` для Safari. HTML/Vite отвечает 200, React build и запросы форм к настоящему API прошли. Это не равно проверке кликов, вёрстки и доступности на реальном телефоне.
- Реальная доставка push требует разрешения пользователя и подписки целевого браузера. iOS/PWA отдельно проверяется на устройстве; её доставка не заявляется проверенной.
- Quick Tunnel проверяется с текущей сетью, постоянный домен и аккаунт Cloudflare принадлежат владельцу. Приложение доступно удалённо только пока соответствующие процессы и Mac включены.
- Качество медицинских выводов не валидировано. Успешная техническая проверка JSON/RAG не подтверждает клиническую достоверность, применимость шкал всем F00–F99 или правовое соответствие MVP.
