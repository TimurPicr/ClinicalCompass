Из авторизации удалены «Картина — целиком», «В центре — человек», «Синтетическая демонстрационная среда» и «Пространство заботы о здоровье». В обзоре врача удалены демонстрационная подпись и число/отсутствие заданий у пациентов. Плашка «Напоминания» убрана из основной и мобильной навигации пациента; существующие настройки доступны через «Настройки уведомлений» в профиле.

У врача появился верхний раздел «Сообщения»: список всех закреплённых пациентов, поиск, последнее сообщение и выбранная переписка. На телефоне список и переписка показываются по очереди с кнопкой «Все диалоги». Возвращение в тот же диалог показывает последние сообщения и сохраняет черновик. Счётчик непрочитанных не имитируется.

## Исправления

- `GET /api/auth/csrf` восстанавливает читаемую cookie из действующей сессии, когда cookie отсутствует или устарела. Токен сессии не меняется; проверки CSRF/Origin сохраняются, истёкшая сессия не восстанавливается.
- Комнаты чата изолированы по пациенту. Поздний ответ старой комнаты не меняет новую комнату. Подтверждение HTTP сразу добавляется в историю и не дублируется WebSocket-событием; запоздалая история не удаляет уже подтверждённое сообщение.
- Подтверждение отправки очищает только отправленный черновик, сохраняя текст, введённый во время ожидания. Вложение после сбоя отправки можно повторно использовать без повторной загрузки.
- Перед подключением восстанавливается CSRF, после переподключения запрашивается пропущенная история. Heartbeat проверяет соединение, резервное чтение работает и без WebSocket. Каждый запрос истории и подготовки соединения ограничен 15 секундами и отменяется при закрытии комнаты.
- Лимит текста согласован с сервером: 5000 символов. Enter отправляет, Shift+Enter вставляет строку, незавершённый ввод IME не отправляется. Прокручивается история внутри чата, а не вся страница.
- Сервер корректно обрабатывает некорректный JSON, бинарные и слишком большие WS-кадры; прекращает доступ после logout, истечения сессии и смены прикрепления пациента.

## API

Добавлен только необходимый новый маршрут `GET /api/chats` для врача. Он возвращает `{patient_id, patient_name, last_message}` для всех его пациентов, включая комнаты без сообщений. Формат `last_message` совпадает с существующим форматом истории и включает сведения о вложении. Список и последние сообщения загружаются одним SQL-запросом и сортируются по дате/ID последнего сообщения, пустые комнаты — в конце. Чужие комнаты недоступны; пациент не получает врачебный список.

Существующие маршруты истории, отправки, вложений и WebSocket сохранены. Изменений схемы БД и миграций нет.
