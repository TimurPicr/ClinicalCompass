# Медицинские источники и локальные модели

Проверено по официальным страницам 23 октября 2026 года. Внешние запросы содержат только общий поисковый запрос к литературе. Карты, дневники и документы пациентов передаются исключительно локальной Ollama. Все пациенты на этом этапе должны быть синтетическими.

## Модели

Официальные теги: [qwen3:4b-q4_K_M](https://ollama.com/library/qwen3:4b-q4_K_M), 4,02B параметров, Q4_K_M, около 2,6 ГБ; [qwen3-embedding:0.6b](https://ollama.com/library/qwen3-embedding:0.6b), Q8_0, около 639 МБ. Размер файла не равен полной потребности RAM. Для Mac M3 Pro 18 ГБ установлен контекст 8192; нагрузки выполняются последовательно, модели выгружаются после запроса (`keep_alive: 0`).

```sh
ollama pull qwen3:4b-q4_K_M
ollama pull qwen3-embedding:0.6b
python -m scripts.check_local_ai
python -m scripts.check_local_ai --patient-id 2
```

Клиент использует документированные [POST /api/chat](https://docs.ollama.com/api/chat) с JSON Schema и [POST /api/embed](https://docs.ollama.com/api/embed) с размерностью 1024. Некорректные векторы и JSON отклоняются. `OLLAMA_URL` принимает только HTTP loopback: `localhost`, `127.0.0.1`, `::1`. Внешних AI API и запасных фиктивных ответов нет.

## PubMed и открытый полный текст

Реализованы [NCBI E-utilities](https://www.ncbi.nlm.nih.gov/books/NBK25499/): `esearch.fcgi` для PMID и `efetch.fcgi` для библиографии в XML. Параметры: `PUBMED_QUERY`, `PUBMED_EMAIL`, `PUBMED_API_KEY`; до восьми недавних статей за проход. Также повторно проверяется до 12 уже известных PMID, выборка меняется между периодами: это позволяет обнаруживать обновления старых документов, не скачивая весь архив. Между запросами выдерживается не менее 0,36 с. Синхронизация идёт каждые `KNOWLEDGE_SYNC_HOURS` часов при работающем обработчике; `0` отключает планировщик.

PubMed не предоставляет универсального разрешения на копирование аннотаций. По умолчанию сохраняются название, журнал, дата, MeSH и идентификаторы, без аннотации. При наличии PMCID адаптер запрашивает [PMC OAI-PMH](https://pmc.ncbi.nlm.nih.gov/tools/oai/) через актуальный адрес `https://pmc.ncbi.nlm.nih.gov/api/oai/v1/mh/`, `GetRecord`, `metadataPrefix=pmc`. Полный текст сохраняется только если ответ содержит статью и явную лицензию Creative Commons/CC0; текст лицензии сохраняется в метаданных. Конкретные ограничения лицензии продолжают действовать. При отказе остаётся библиография; это отмечается в журнале. Карточка без полного текста не является доказательством эффективности лечения.

Старый PMC OA Web Service **не используется**: [PMC сообщает о прекращении его работы с 25 августа 2026 года](https://pmc.ncbi.nlm.nih.gov/tools/oa-service/). Разрешённые методы автоматического получения PMC перечислены на [официальной странице разработчиков](https://pmc.ncbi.nlm.nih.gov/tools/developers/). Учитывайте [NCBI Disclaimer and Copyright](https://www.ncbi.nlm.nih.gov/About/disclaimer.html).

## Российские инструкции и клинические рекомендации

[ГРЛС](https://grls.rosminzdrav.ru/) и [рубрикатор Минздрава](https://cr.minzdrav.gov.ru/) проверяются на доступность. На странице ГРЛС есть отдельный процесс предоставления доступа к БД; публичный интерфейс рубрикатора зависит от JavaScript. В проекте не настроен стабильный официально документированный API массовой загрузки **полных инструкций и рекомендаций**. Это ограничение адаптера, а не утверждение об отсутствии каких-либо API у ведомств.

Адаптер сохраняет `manual_import_required`, HTTP-ошибку или диагностику ограничения в `source_logs`. Он не имитирует загрузку, не перебирает скрытые endpoint, не обходит CAPTCHA и авторизацию. Рабочий путь — скачать разрешённый PDF/текст вручную и импортировать через интерфейс врача либо CLI:

```sh
python -m scripts.import_knowledge ./instruction.pdf \
  --source grls --external-id registration-number --title 'Инструкция препарата' \
  --url 'https://grls.rosminzdrav.ru/' --category drug_instruction \
  --version '2026-01' --ingredients 'действующее вещество'
python -m scripts.import_knowledge ./guideline.pdf \
  --source minzdrav --external-id guideline-number --title 'Клиническая рекомендация' \
  --url 'https://cr.minzdrav.gov.ru/' --category clinical_guideline
python -m scripts.sync_sources
python -m app.backend.ai.worker
```

Используйте точную официальную ссылку на документ, а не главную страницу из примера. Категории: `drug_instruction`, `clinical_guideline`, `publication`. Для источника хранятся внешний идентификатор, название, URL, дата публикации, дата загрузки, внутренняя версия, версия издателя, checksum, метаданные и разрешённый текст. Старые версии сохраняются. Неизменённый checksum не создаёт повторной индексации. Новая версия становится активной только после успешной индексации; прежняя доступна до этого момента.

## RAG и ограничения AI

Фрагменты примерно по 1400 символов с перекрытием; PDF сохраняет номера страниц. В PostgreSQL используется pgvector с косинусным расстоянием, затем ранжирование с текстом и метаданными, включая действующие вещества. В запрос к LLM попадает до пяти фрагментов и 5500 символов источников. Поиск врача работает по тексту и метаданным и при недоступной/занятой модели, явно возвращая `semantic_available: false`.

Факты извлекаются локальной моделью; дословная цитата должна присутствовать в исходном фрагменте. Факты остаются `verified: false` и никогда не превращаются в клинические правила. Ответ анализа валидируется Pydantic; допускаются только ID/URL/страницы действительно найденных фрагментов. Даже валидная структура не доказывает медицинскую правильность. Промпты маркируют данные как недоверенные; у модели нет инструментов изменения лечения. Рекомендации сериализуются только для врача. AI может повысить тревогу, но не снизить статус критического правила.

Для анализа пациента действует дополнительный фильтр SQL: `clinical_only=True` исключает источник `demo` и документы с `content_type=bibliographic_metadata`. Синтетические примеры и библиография доступны в общем поиске врача для проверки интеграции, но не поступают в клинический контекст модели. Одной инструкции в промпте для этого недостаточно: ограничение применяется до формирования ответа.

Очередь PostgreSQL хранит статусы, число попыток, время следующей попытки и безопасную категорию ошибки. Общая advisory lock сериализует работу моделей между процессами и HTTP-поиском. После завершения процесса блокировка освобождается PostgreSQL; следующий обработчик восстанавливает незавершённые задачи. Повторы ограничены `AI_MAX_RETRIES`, используется задержка с ростом до 300 секунд. Основные функции не зависят от доступности Ollama.

## Документы пациентов и OCR

PDF/JPEG/PNG/WebP сохраняются под случайным именем в закрытом `UPLOAD_DIR` (права файла 0600). Расширение проверяется по содержимому; PDF до 60 страниц, изображения до 30 МП, размер — `MAX_UPLOAD_MB`. Скачивание требует сессии и проверки принадлежности пациенту/лечащему врачу. Каталог не публикуется как static.

Для текстового PDF используется pypdf; при недостатке текста — локальные `pdftoppm` и `tesseract -l rus+eng`. Установка macOS:

```sh
brew install tesseract tesseract-lang poppler
tesseract --list-langs
```

OCR ошибается на почерке, бликах, поворотах, плохом скане и табличной разметке. Страница обрабатывается с ограничением времени; при отсутствии утилиты задача завершится диагностируемой ошибкой, без подмены успешным извлечением. Предложения модели включают поле, значение, страницу и точную цитату; если цитата не найдена, результат отклоняется. До проверки статус `unconfirmed`. Подтверждение или отклонение врачом сохраняется с автором/временем и аудитом; карта автоматически не перезаписывается.

- `python -m pytest tests/test_ai.py tests/test_knowledge.py -q`: 15 тестов прошли без Ollama, включая повторы/восстановление очереди, дедупликацию, запрет вымышленных ссылок, конкурентное красное правило, защиту от активации устаревшей версии при повторе, фильтрацию синтетических и библиографических документов из клинического контекста, права на файлы и неизменность проверенных предложений.
- Реальная PostgreSQL 16 с pgvector: миграция, сохранение двух фрагментов синтетического источника с настоящими 1024-мерными векторами; семантический запрос вернул эти фрагменты через косинусное расстояние в PostgreSQL.
- `python -m scripts.check_local_ai`: настоящие локальные модели вернули 1024-мерный embedding и валидный JSON; `--patient-id 2` выполнил полную задачу анализа синтетического пациента. Модель не сослалась на синтетический материал как на клиническое доказательство.
- Дополнительно проверен реальный первичный источник — [оригинальное руководство авторов PHQ/GAD](https://www.phqscreeners.com/images/sites/g/files/g10016261/f/201412/instructions.pdf), 9 страниц. Оригинал сохранён локально в `var/reference/phq-gad-original-instructions.pdf`; визуально проверены страницы 6 (подсчёт баллов) и 8 (условия использования). В базу импортировано собственное фактическое изложение только этих двух страниц, с исходной нумерацией, источником `original_author`, категорией `publication` и непроверенными AI-фактами. Это не российская клиническая рекомендация и не валидированный перевод инструмента. Указание public domain на странице 8 относится к шкалам из таблицы 1; явная лицензия на весь текст руководства не утверждается. Настоящие модели проиндексировали материал и ответили на вопрос о подсчёте PHQ-9/GAD-7; валидатор подтвердил ID фрагментов, точный URL и страницы 6/8. Артефакт выполненной проверки: `var/reference/phq-gad-rag-verification.json` (локальный, каталог `var/` не включён в Git).
- После введения механического фильтра клинических источников все три основных демонстрационных пациента повторно проанализированы настоящей моделью: каждая задача завершилась с первой попытки. Для двух пациентов модель оставила список внешних источников пустым; для третьего использованы только страницы 6/8 руководства авторов. При проверке каждой непустой ссылки подтверждены первичный источник, ID фрагмента, URL и страница. Старые результаты сохранены в истории, последние результаты не цитируют синтетические материалы или библиографические карточки.
- Реальная очередь обработала синтетическое изображение через Tesseract rus+eng и локальную LLM: одна страница, четыре предложения с проверенной дословной цитатой и номером страницы; статус оставлен `unconfirmed`.
- Отдельно проверен PDF со сканированным изображением: отсутствие текстового слоя, рендер `pdftoppm`, OCR и распознавание синтетической контрольной строки.
- `python -m scripts.sync_sources`: официальный PubMed API вернул восемь библиографических карточек. Для одной статьи PMC полный текст был недоступен, что записано как `partial`. ГРЛС и рубрикатор Минздрава из среды проверки ответили `ConnectTimeout`; записан `unavailable`, доступен ручной импорт. Эти ограничения не выдаются за успешную загрузку инструкций или рекомендаций.

Это проверка технического потока на синтетических данных, а не клиническая валидация AI или заключение о пригодности приложения для реальных пациентов.
